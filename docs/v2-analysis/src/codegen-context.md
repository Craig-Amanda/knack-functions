# Rules for writing a knackFunctionsV2.js section

You are writing one section of `knackFunctionsV2.js`. The file is assembled from `scratchpad/v2/NN-name.js` (implementations) and `scratchpad/v2/NN-name.shims.js` (compatibility shims) by `scratchpad/assemble.mjs`, in filename order, after the header and before an auto-generated "Not yet ported" index. You write ONLY your two section files and ONE test file; never edit `knackFunctions.js` or any other section.

## Inputs
- `scratchpad/plan.json` → `entries` filtered to your chunk id. Implement every entry with `wave === 1`. Entries with wave 2 or 3 are NOT written now (the assembler lists them as pending automatically). Read each entry's `verdict`, `proposedSignature`, `proposedReturns`, `modernisations`, `behaviourRisks`, `shimRequired`, `shimShape`, `canonicalReplacement`, `_corrections` (reviewer corrections already applied) and `rationale`.
- `scratchpad/knack-context.md` → the binding policy (signature definition, Knack facts, modern-JS targets).
- `scratchpad/v2/00-foundation.js` → primitives you MUST reuse instead of re-implementing. Read it in full. In short:
  - `resolveElement(input, root = document)` → Element|Document|null; accepts selector, Element, Document/Fragment, jQuery, array/NodeList.
  - `resolveElements(input, root = document)` → Element[]; accepts selector, Element, NodeList/HTMLCollection, jQuery, arrays mixing any of those.
  - `toJQuery(input)` → jQuery collection (or Element[] if jQuery is absent); use in shims where V1 returned a jQuery object.
  - `getById(id, { context })`, `getViewRootElement(viewRef)`, `getFieldWrapper(fieldId, root = document)`.
  - Ids and values go through the shared singletons, never ad-hoc regexes: `knackNavigator.normalizeViewId/normalizeFieldId/normalizeSceneId` for ids, `knackNavigator.getViewObject/getFieldMeta/getFieldType/getSceneInfoForView/...` for Knack metadata, and `knackValueResolver.toStringSafe/toNumberValue/toBooleanValue/toConnectionRef/resolve/...` for coercing and reading record values. Check their method lists before hand-writing a conversion.
  - `ensureStyle(id, cssText)` (idempotent style injection), `fireEvent(target, type, detail?)` (native bubbling dispatch; also reaches jQuery/Knack/Chosen handlers), `onKnackEvent(eventName, handler)` → off() (binds with jQuery because Knack triggers through jQuery).
  - `debounce(fn, wait)`, `escapeHtml(value)`, `cssEscape(value)`, `isPlainObject(v)`, `isNodeList(v)`, `isjQueryInstance(v)`, `warnDeprecated(oldName, replacement)`.
- The V1 source of each function (use `sed -n 'A,Bp' knackFunctions.js` with the plan's invStart/invEnd) and of every in-file helper it calls.

## Implementation rules
1. Same global name for every ported function unless the plan makes that name a shim (verdict dedupe/deprecate/remove-dead, or `signatureChanges === true`). A changed signature ships under a NEW name (UK spelling, descriptive) and the OLD name goes in the `.shims.js` file with the OLD parameter list exactly (tests compare parameter lists textually with V1).
2. Adding an optional trailing parameter is allowed without a shim ONLY if the plan says so; record it in `tests/v2/signature-exceptions.json` as `{ "name": { "v1": "<v1 params>", "v2": "<v2 params>", "reason": "..." } }` (merge, do not overwrite others).
3. Keep every behaviour V1 had for inputs V1 accepted: sync/async, errors thrown, class names / ids / data attributes / custom events the DOM or CSS rely on. Return types: if V1 returned a jQuery collection, the V2 implementation returns native `Element`/`Element[]` under a NEW name and the OLD name is a shim that returns `toJQuery(newName(...))` (see rule 4). Widening accepted inputs is fine. Fixing a plan-documented bug is fine when the plan says so; note it in the JSDoc.
4. Modern, succinct JavaScript per `knack-context.md`: native DOM, `const`/`let`, optional chaining, early returns, `Intl`, `async/await`, `MutationObserver` over polling, idempotent `ensure*` via `ensureStyle`. NO jQuery in implementation code (repo-owner rule) except the three Knack-imposed cases: Knack lifecycle events (bind through `onKnackEvent`), the Chosen select plugin (`chosen:updated` / `.chosen()`), and the jQuery UI date/time pickers (`.datepicker()` / `.timepicker()`). Isolate each such call on one line with a comment saying which exception it is. `$(el).trigger('change')`, `.val()`, `.css()`, `.find()`, `.closest()`, `.on('click')` etc. are all replaced with native equivalents (`fireEvent`, `.value`, `style`, `querySelector`, `closest`, `addEventListener`). jQuery may appear in `.shims.js` only to wrap a return value with `toJQuery()`.
5. 4-space indent, single quotes, semicolons, JSDoc on every function (`@param` with types, `@returns`), UK spelling for new identifiers only, no `//knack` tag comments, no trailing `};` after function declarations, no commented-out code, no console.log (use `errorHandler.handle(error, context, 'functionName')` for errors; `console.warn` only through `warnDeprecated`).
6. Each shim: JSDoc with `@deprecated Use newName()` and the reason, first statement `warnDeprecated('oldName', 'newName()')`, then the mapping. Keep it to a few lines. A `remove-dead` global becomes a shim that warns and either no-ops or delegates to the trivial equivalent, so page code referencing it does not throw.
7. Do not declare a global another section owns: everything in 00-foundation.js, plus `KnackNavigator`/`knackNavigator`, `KnackValueResolver`/`knackValueResolver` (sections 01/02). Ids and Knack values MUST go through `knackNavigator` and `knackValueResolver` (both are real V2 sections now).
8. Private helpers that are not V1 globals are fine as top-level functions ONLY if several functions share them; name them clearly and give them JSDoc (they become globals too). Otherwise inline.
9. Dead statements V1 executed at load time (e.g. the F2 `debugger` keydown handler) are not re-created unless the plan says to keep them.

## Tests you must write: `tests/v2/<section>.test.cjs`
- Use `tests/v2/harness.cjs`: `both({ names, html, before }, scenarioFn, arg)` runs `scenarioFn` in a V1 page and a V2 page (V2 falls back to V1 for names it does not declare yet) and returns `{ v1, v2, v1Console, v2Console }`; `realm({ file: V2, names, html })` for V2-only checks. See `tests/v2/foundation.test.cjs` for the pattern (`expectSame`). Stubs for `Knack`, `ktl`, `errorHandler` are in `tests/v2/stubs.js` (extend via the `before` script, not by editing stubs.js).
- For every ported function: at least one differential scenario (same DOM fixture, same calls, deep-equal result including resulting DOM state where relevant), plus edge inputs (missing element, null, jQuery input where V1 accepted one).
- For every shim: call it with the OLD argument forms and assert the result/DOM equals V1's.
- Functions that need a real Knack runtime (navigation, API calls): test the parts that run against the DOM/stubs; assert `errorHandler` was called where V1 would have reported.
- Run: `KF_V2_PATH=<preview> KF_TEST_DEPS=/tmp/claude-0/-home-user-knack-functions/8507bada-7b16-5823-bfb2-30be071ef228/scratchpad/testdeps/node_modules node --test tests/v2/<section>.test.cjs` where `<preview>` is produced by `SP=<scratchpad> OUT=<scratchpad>/v2-preview-<section>.js node <scratchpad>/assemble.mjs` (assemble first, after writing your section files; the assembler includes every section present, so other agents' work may appear too - that is fine).
- Also run `node --check` on both of your section files and `node <scratchpad>/assemble.mjs` must report no DUPLICATES. All tests must pass before you finish; if a differential test shows V1 behaviour you believe is a bug, keep V1 behaviour unless the plan entry says to fix it, and record the disagreement in your final report.
